# Case Study — M Tech Square Website

## For future Claude

**Publishable now, no permission needed** — the client is the parent group. This is the case study with the *most existing narrative material*: Code Square already published a ~10-part Arabic carousel telling this story on Facebook between 2026-08-24 and 2026-08-31. That narrative is recorded verbatim in `[[2026-09-02 - Facebook Page Evidence]]` and is reused here, preserved in Arabic. This is a **re-cut, not a new write**.

What it lacks is any number and any date. Every gap below is marked `❓ NEEDS FROM FOUNDER:`. Do not fill them by inference.

Structure follows `[[Case Study Framework]]`.

## 1. Client and context (stated)

**M Tech Square** — the parent group Code Square belongs to, operating under the line **"BEYOND SQUARES — Driving the future of Egyptian innovation through a unified ecosystem of technology, education, sustainability, and medical excellence."** The group holds multiple entities, each with its own service and its own audience: Code Square (technology), Techno Square (education), Online Techno Square (distance learning), Digital Square, M Square, and M Nature.

Code Square built the group's corporate website — the site that now hosts Code Square's own pages at `mtechsquare.com/code-square/`.

`❓ NEEDS FROM FOUNDER:` When did this project start and when did it launch? Was it built by Code Square alone, or with people from other group entities?

---

## 2. The problem — in the client's own words (stated, published verbatim)

The story Code Square published opens on the first meeting, where the question asked was not the expected one:

> **"إيه اللي ناقص؟"**

The finding that followed, in the company's own published words: a company that builds digital presence for others **had no digital presence of its own.**

The deeper finding: M Tech Square is a parent company with multiple entities beneath it, each with a distinct service and audience — **but clients only ever saw one fragment.** Someone who met Techno Square never learned that Code Square existed.

---

## 3. Why it mattered commercially (stated)

From the published narrative: sales and marketing relied on **verbal explanation, presentations, and printed materials.** There was **no digital portfolio.** Every conversation started from zero, and the full scale of the group — the thing that makes it credible — had to be re-explained by a human being every single time.

The audience problem compounded it: digital services are not geography-bound, so the audience was never Egypt-only. But nothing existed in English, so anyone outside Arabic was unreachable.

`❓ NEEDS FROM FOUNDER:` Roughly how often was a presentation or printed profile being sent out per month before the site existed? This is the closest thing to a "before" number this project has.

## 4. Our approach — mapped to the four-phase methodology

*(The four phases are the canonical model from the Code Square website: التأسيس → المعمارية → الهندسة → الإطلاق والتطوير. What is recorded below in each phase is what the published narrative evidences; anything not evidenced is marked.)*

**التأسيس — Discovery.** The engagement did not begin with design. It began with the question **"إيه اللي ناقص؟"** — what is missing — which surfaced the real problem: not an absent website, but an invisible group structure. Audience was defined next, and defined as international rather than Egyptian, which set the bilingual requirement before a single screen was drawn.

**المعمارية — Architecture.** The organising idea was **Universe**: M Tech Square is the universe, each entity is a planet with its own world, audience, and personality, all orbiting the same space — **"مختلفين… لكن مش منفصلين."** ("Different… but not separate.") This solved the actual problem: it let each entity keep a distinct identity without fragmenting the group. The information architecture also required **Arabic and English as two full parallel experiences, not a translation layer.**

**الهندسة — Engineering.** Each entity got its own visual world:
- **Code Square** — the site itself is the proof. 3D models and animation make the technology part of the experience, carrying the message **"Custom-built. مش Copy & Paste."**
- **Techno Square** — education as a journey. Images, illustrations, and infographics for a student audience, with the mascot **تاتا 🤖** used as a companion through the journey, not as decoration.
- **Online Techno Square** — distance still deserves an experience. Glassmorphism and holographic elements, with the online enrolment form wired **directly into the Techno Square dashboard.**

`❓ NEEDS FROM FOUNDER:` Which framework and stack were chosen, and why? The site evidence shows Angular, GSAP, Three.js, Spline, Rapier physics — was this a deliberate architecture decision worth explaining, or accumulated?

**الإطلاق والتطوير — Launch & Iterate.** The site is live at `mtechsquare.com`. The project carries the status label `تحديثات جارية` (ongoing updates), so this is an iterating asset rather than a closed delivery.

`❓ NEEDS FROM FOUNDER:` What has shipped since launch? Naming two or three post-launch improvements would evidence the "Launch & Iterate" phase and the retainer model in the offer ladder.

## 5. What we built (stated)

- A corporate website presenting the group's full technology ecosystem, with cinematic animation (verbatim: *موقع مؤسسي يستعرض النظام البيئي التكنولوجي للمجموعة برسوم متحركة سينمائية*)
- A multi-entity information architecture — one universe, six distinct entity worlds
- Full Arabic and English parallel experiences (not translation)
- 3D and animated experience layer: Three.js, Spline 3D viewer, GSAP with ScrollTrigger and ScrollSmoother
- A per-entity design token system — each entity has its own accent colour on a shared navy and gold foundation
- **An online enrolment form wired directly into the Techno Square dashboard** — a real system integration, not just a contact form
- A contact and project-request form with a structured brief (project name, budget band, project type, details) and a stated 24-hour response commitment

**Honest scope note for anyone publishing this:** the delivered site currently has an **expired TLS certificate**, no server-side rendering, no sitemap, no robots.txt, and no page-level meta — documented in `[[2026-09-02 - Website Evidence (mtechsquare.com-code-square)]]`. Do **not** publish this case study as a technical-excellence showcase until those are fixed, because a prospect who clicks through lands on a browser security warning. Publish it as a **design, IA, and brand-architecture** case study, and fix the technical layer first (Priority 0, `[[Foundation Brief]]` §9).
